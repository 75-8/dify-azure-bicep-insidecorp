# 70_secret

## スコープ
- シークレット管理方針
- Key Vault 連携
- 運用（投入/ローテーション/監査）

## 方針
- 機微情報は Azure Key Vault に一元管理する。
- IaC テンプレート/パラメータ/CI ログへシークレット値を保持しない。
- 参照は Managed Identity + RBAC（またはアクセスポリシー）で最小権限化する。

## 対象シークレット
- AOAI API Key
- DB 接続文字列/パスワード
- Redis 接続情報
- TLS 証明書関連シークレット（必要時）

## 連携要件
- `aca-env` は Container App Secret として Key Vault 参照を利用する。
- `app-gateway` は証明書参照が必要な場合 Key Vault を参照する。
- `deploy.ps1` はシークレット値を表示しない（マスク/非出力）。

## ローテーション要件
- シークレットは定期ローテーションする。
- ローテーション時の影響最小化のため、バージョン付き参照または二重化手順を定義する。
- ローテーション後の疎通確認（API/DB/Redis）を Runbook に含める。

## 受け入れ基準
- 主要シークレットが Key Vault で管理されている。
- IaC/CI ログにシークレット平文が出力されない。
- 参照権限が最小権限で付与されている。
- ローテーション手順と復旧手順が文書化されている。
