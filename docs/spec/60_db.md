# 60_db

## スコープ
- PostgreSQL (Flexible Server / pgvector)
- Azure Cache for Redis
- Storage Account (Blob / Azure Files)

## 共通セキュリティ方針
- すべてのデータ・キャッシュ・ストレージリソースは VNet 内部に閉域配置し、インターネット（パブリックネットワーク）からの直接アクセスを無効化する。
- 接続は Private Endpoint および専用委譲サブネットを介して行い、Private DNS Zone による名前解決を構成する。

## 各リソース詳細仕様 (Bicep実装準拠)

### 1. PostgreSQL (詳細は [postgresql.bicep](file:///home/sept/dify-azure-bicep-insidecorp/infra/modules/postgresql.bicep))
- **バージョン**: PostgreSQL Flexible Server `version: '14'`
- **SKU / サイズ**: Burstable `Standard_B1ms` (ストレージ: 32GB)
- **可用性・バックアップ**: バックアップ保持期間 7 日 (地理冗長無効)、HA（高可用性）構成は無効
- **作成データベース**:
  - `dify`: Dify 管理用DB
  - `vector`: ベクトルDB（pgvector 用）
- **拡張機能**: データベース初期化時に `azure.extensions` 設定を通じて `uuid-ossp` および `vector` 拡張モジュールを自動有効化。
- **ネットワーク**: 専用の `PostgresSubnet` に委譲され、プライベート DNS リンク (`privatelink.postgres.database.azure.com`) が構成される。

### 2. Azure Cache for Redis (詳細は [redis-cache.bicep](file:///home/sept/dify-azure-bicep-insidecorp/infra/modules/redis-cache.bicep))
- **SKU / サイズ**: Basic `C0` (容量 0)
- **バージョン**: Redis `6`
- **セキュリティ要件**: Non-SSL ポート (6379) の無効化、最小 TLS バージョン `1.2`、パブリックネットワークアクセスの無効化。
- **ネットワーク**: `PrivateLinkSubnet` にプライベートエンドポイント (`pe-redis`) を配置し、プライベート DNS リンク (`privatelink.redis.cache.windows.net`) で名前解決。

### 3. Storage Account (詳細は [storage.bicep](file:///home/sept/dify-azure-bicep-insidecorp/infra/modules/storage.bicep))
- **SKU / 種類**: `Standard_LRS`、種類: `StorageV2`、ホットティア
- **セキュリティ要件**: Https 接続のみ許可、パブリックアクセス無効、ネットワーク ACL デフォルトルールは `Deny`。
- **ネットワーク**: `PrivateLinkSubnet` 内に `blob` および `file` のそれぞれのサブソースに対してプライベートエンドポイント (`pe-blob`, `pe-file`) を配置し、プライベート DNS リンクで名前解決。
- **ファイル共有共有 (File Shares)**: Dify コンポーネント用の以下のファイル共有を自動プロビジョニング (割り当て上限 50GB)：
  - `nginx`, `sandbox`, `ssrfproxy`, `pluginstorage`
